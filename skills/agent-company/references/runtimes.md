# ホストへの渡し方

この資料で区別するのは、会社の担当者とホストの実行機能。職種のMarkdownは指示として渡す資料であり、ホストへ登録するエージェント定義ではない。

## Codex

現在使える起動ツールの引数を確認する。エージェント種別を選べる場合、汎用の判断には `default`、実装には `worker`、読取り中心の調査には `explorer` が選択肢になる。種別を選ぶ引数がない画面では、そこで提供されている標準のサブエージェントを使う。

`CTO` などの職種名を、未登録の種別として渡さない。名前や職務は呼出し時の指示へ入れる。モデルと推論設定は利用者の設定を引き継ぎ、このスキルのために変更しない。

利用可能な追加指示、結果待ち、停止の機能を使う。返ってきたハンドルは、ホストと親セッションの情報が分かれば一緒に記録する。別セッションや別製品でも同じIDが有効とはみなさない。

## Claude Code

`Agent` の種別に `general-purpose` が用意されていれば、それに職務と依頼を渡す。読取り専用の調査で能力が合う場合は `Explore` も使える。実際のツールにない種別や引数を作らない。

会社の進行はメインの会話に残す。そのため `SKILL.md` に `context: fork` や `agent:` を付けない。通常のサブエージェントは親の会話や読み込み済みのスキルをそのまま持たないので、共通の取り決めと職種資料、依頼の前提を明示して渡す。

継続用のハンドルが使える場合は同じ担当へ追加指示できる。使えない場合は、社員メモと依頼票から仕事を再構成する。多段起動や実験的なチーム機能を有効にする必要はない。

## どちらでも共通の判断

- 標準サブエージェントが使えなければ、その制約を伝え、適した仕事をメインの会話で役割を明示して行う。実際には行っていない委譲や独立レビューを装わない。
- 子がスキルのファイルを読めるなら絶対パスと必読指示を渡し、読めないなら必要な本文を渡す。全職種や全履歴を一括で送り込まない。
- メインの会話が全社員を呼ぶ。上司が部下へ任せたい仕事は提案として戻してもらい、進行役が次の呼出しへ変える。
- 職種の指示はホストの権限境界を増やさない。読取りのみの依頼でも、実際の制限はホスト設定に従う。
- 利用者の認証方法を維持する。別のCLI、APIキー、MCPサーバーを起動や課金の代替手段として追加しない。Skillだけでサブスク残量や請求上限を保証することはできない。
- ホストを終了した後も働き続けるとは約束しない。記録からの再開と、常駐する実行は別の機能。

## 配布と検出

配布するのは `agent-company/` 全体。`agents/` と `references/` も同じ位置関係で含める。`name` と `description` だけの共通フロントマターを使い、ホスト固有の登録ファイルを生成しない。

任意の保存先に置いただけでは、自動検出されるとは限らない。利用者が選んだ範囲で、フォルダ全体を次の場所へ配置またはリンクする。

| ホスト | プロジェクト内 | 個人用 | 呼出し |
| --- | --- | --- | --- |
| Codex | `.agents/skills/agent-company/` | `~/.agents/skills/agent-company/` | `$agent-company` |
| Claude Code | `.claude/skills/agent-company/` | `~/.claude/skills/agent-company/` | `/agent-company` |

会社を作る依頼を理由に、個人用へのインストールや設定変更まで行わない。新しいスキルが見つからない場合は、そのクライアントの再読み込み方法を使う。
